An **extension point** is a typed list the editor reads. A plugin adds a value with `context.contribute(POINT, value)` and keeps the returned disposable in `context.subscriptions`.

```ts
import { STATUS_BAR_ITEMS } from '@nanoforge-dev/editor-sdk/ui';

context.subscriptions.add(
  context.contribute(STATUS_BAR_ITEMS, {
    id: 'counter.total',
    alignment: 'right',
    text: derived([count], (value) => `Count: ${value}`),
    command: 'counter.add',
  }),
);
```

Several points can also be filled from the [manifest](./manifest#contributions), without code: widgets, menus, keybindings, keymap presets, settings, themes, tours and document editors.

## Workbench

From `@nanoforge-dev/editor-sdk/ui`.

| Point              | A value is                                                                                                                  | Manifest key    |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- | --------------- |
| `WIDGETS`          | A panel or a screen: `id`, `title`, `icon`, `kind`, `defaultSlot`, `order`…                                                 | `widgets`       |
| `WIDGET_VIEWS`     | The view of a widget: `{ id, component }` (a Svelte component) or `{ id, mount(element, instance) }` for another framework. |                 |
| `MENU_BAR`         | A menu of the menu bar: `{ id, title, order }`.                                                                             |                 |
| `MENU_ITEMS`       | An entry of a menu, a submenu or a context menu.                                                                            | `menus`         |
| `KEYBINDINGS`      | A default shortcut: `{ key, command, when, args }`.                                                                         | `keybindings`   |
| `KEYMAP_PRESETS`   | A named set of shortcuts.                                                                                                   | `keymapPresets` |
| `TOOLBAR_ITEMS`    | A button of the top bar: `{ id, icon, title, command, args, when, toggled, order }`.                                                     |                 |
| `STATUS_BAR_ITEMS` | An item of the status bar: `{ id, alignment, text, tooltip, command, when }`. `text` is an observable.                      |                 |
| `SETTINGS_PAGES`   | A page of the Settings dialog with its own editor. It names the settings it edits, which then leave the category list.      |                 |
| `THEMES`           | A color theme.                                                                                                              | `themes`        |
| `TOURS`            | A guided tour: steps over the editor, ahead on real events. `TourServiceToken` starts one.                                  | `tours`         |

## Files

| Point              | A value is                                                                                                                                                                                      |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FILE_TEMPLATES`   | A "New…" entry of the Files panel: `{ id, title, icon, category, when, defaultName, create({ folder, name }) }`, which returns (or resolves with) the files to write, `{ path, content }`; the first one opens. `when` sees `fileFolder` and `appType` (`client`, `server`, `lib`, empty outside apps). |
| `FILE_ACTIONS`     | An entry of the context menu of files: `{ id, title, icon, command, group, order, when }`. The command gets the selected paths. `when` sees `fileKind`, `fileExtname`, `fileReadOnly`, `fileSelectionCount`. |
| `FILE_ICONS`       | The icon of files or folders matching a glob: `{ pattern, icon, priority }`, with `folder: true` and `iconOpen` for folders.                                                                                                                               |
| `FILE_DECORATIONS` | Marks on files, as Git does: `{ id, changes, decorate(path, kind) }`. `changes` is an observable that fires when marks must be read again; `decorate` returns `{ badge, tone, tooltip }` or `undefined`, and the first answer wins.                                                                                                      |

## Game and Scene screens

| Point               | A value is                                                                              |
| ------------------- | --------------------------------------------------------------------------------------- |
| `VIEWPORT_TOOLS`    | A button of the Game or Scene toolbar: `{ id, screen, icon, title, command, toggled, when, order }`. |
| `VIEWPORT_OVERLAYS` | A component drawn over the running game or the scene (gizmos, debug views): `{ id, screen, component }`. |

## Project

From `@nanoforge-dev/editor-sdk`.

`PROJECT_CHECKS`: a check of the open project, for the Project screen's **Adapt to the editor** report (see [Bring an existing project](../editor/adapt-a-project)). `run(project)` resolves with suggestions: an `id` (stable, so a dismissed one stays dismissed), a `title`, a `detail` (what the editor can't do, why the change helps) an optional `app`, and either a `fix` or an `action` (`{ title, run() }`, run at once). A fix computes its change without writing anything: `recordChanges` runs workspace operations on the files kept in memory, and the editor shows the result as a diff before applying it as one undo step. It refuses to apply while a file it changes has unsaved edits.

```ts
import { PROJECT_CHECKS, recordChanges, workspaceIo } from '@nanoforge-dev/editor-sdk';

context.contribute(PROJECT_CHECKS, {
  id: 'counter.config',
  run: async (project) => {
    const io = workspaceIo(project);
    if (io.exists('counter.json')) return [];
    return [
      {
        id: 'counter.config',
        title: 'Add a counter config',
        detail: 'The Counter panel reads counter.json: without it, it starts at 0 every time.',
        fix: {
          title: 'Add counter.json',
          changeset: () =>
            recordChanges(io, 'Add counter.json', (memory) => memory.write('counter.json', '{ "start": 0 }\n')),
        },
      },
    ];
  },
});
```

Checks run when a project opens, when a check is contributed, and after files change. Run the expensive parts in the code worker (an analyzer), never on the page.

## Points of other plugins

A plugin can define its own points with `defineExtensionPoint<T>(id)`, and others contribute to them by declaring the same id. The ECS plugin has four:

| Id                 | A value is                                                                                                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ecs.fieldEditors` | The inspector field of a value type, or of one referenced type.                                                                                                                     |
| `ecs.paramPresets` | A visual preset that merges several constructor parameters into one control.                                                                                                        |
| `ecs.entityActions` | An action on an entity of the Hierarchy: `{ id, title, command, when }`. The command gets `{ app, entity, path }`; `when` sees `ecsEntity` and `ecsComponent:<class>` (`ecsComponent:Position`). |
| `ecs.sources`      | What the ECS widgets edit for an app: a file and the function holding its spawns (`main`, or a method of a class), and read-only locations shown with it. The scene plugin uses it. |

Declare `@nanoforge/ecs` in your manifest's `dependencies` to contribute to them.

## Reading a point

```ts
const items = context.contributions(FILE_TEMPLATES); // observable of contributions
items.subscribe((list) => console.log(list.map(({ value, owner }) => `${owner}: ${value.id}`)));
```
