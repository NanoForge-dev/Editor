A game written before the editor, or by hand, works in it as it is. Some ways of writing it, though, keep parts of the game out of the panels. The **Project** screen counts them under **Adapt to the editor**, and **Show suggestions** lists them: one card each, saying what the editor can't do and why the change helps.

Nothing changes on its own. A card's button shows the change first: every file it creates, changes or removes, with its lines. **Apply** makes it as one step: `Ctrl+Z` on the Project screen puts every file back. When the project is a Git repository, the preview reminds you to commit first, so you can compare afterwards. A file with unsaved changes is never overwritten: save it first.

**Dismiss** puts a card away for this project. _Settings › Editor › Project › Dismissed suggestions_ brings it back.

## What the report finds

| Card                                        | What the editor can't do                                                                                                                                            | The change                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Move … out of main.ts**                   | Components and systems defined in the app's entry file are not in the Components panel, have no documentation in the Inspector, and can't move to a shared library. | Each goes to a file of its own in the app's `components/` or `systems/` folder, with only the imports it uses. A helper only they use goes with them (an exported one stays: other files import it). `main.ts` imports them back. Refused when they use something `main.ts` keeps (a layer, a constant): they would import `main.ts` while it imports them, so move that to a module of its own first. |
| **Split components.ts**                     | Several components (or systems) in one file can only be moved, renamed or removed together.                                                                         | One file each. Every file that imported them imports each from its new file.                                                                                                                                                                                                                                                                                                                           |
| **Share Position**                          | The client and the server each have their own copy: a change to one is not made to the other.                                                                       | When the copies are the same (their imports and strings too), the component moves to a [shared library](components#share-between-client-and-server) both apps use (`libs/shared`, named after the project's scope, created if the project has none), and every import points at it. When they differ, or share a file with other items, the card says what to do first.                                |
| **… imports main.ts**                       | A component or system that imports the app's entry file can't move to a shared library.                                                                             | Nothing automatic: move what it uses from `main.ts` (a layer, a constant) to a module of its own.                                                                                                                                                                                                                                                                                                      |
| **Make main's entities a scene**            | Entities `main` makes are there for the whole game.                                                                                                                 | They move into a scene, `Game`, loaded when the game starts. See [Scenes](scenes). `@nanoforge-dev/scene` goes in the app's `package.json` when another `package.json` of the project names it; otherwise the preview says to add it by hand. Refused when they use variables of `main` itself, or what `main.ts` exports (it would import the scene that imports it).                                 |
| **Register the editor library**             | Without `@nanoforge-dev/editor-lib`, a game plays without the editor bridge: no Pause, Step or Stop, no World, Profiler or Network.                                 | `app.use(new EditorLibrary())` in `main.ts`, and the dependency in `package.json`.                                                                                                                                                                                                                                                                                                                     |
| **List … in libs**                          | An app imports a shared library its `nanoforge.config` does not list: the editor does not offer that library's items in the app.                                    | The library is added to `libs` and to the app's `package.json`.                                                                                                                                                                                                                                                                                                                                        |
| **Install the dependencies**, **Install …** | Without `node_modules`, or without an engine library the app declares, the game can't build and the code editor knows nothing of the engine.                        | Runs the project's package manager. A library not published on npm yet (`@nanoforge-dev/scene`) is linked from an engine checkout.                                                                                                                                                                                                                                                                     |

<Note>
  `@nanoforge-dev/scene` and the editor library with the bridge are not on npm yet. A project turned
  into scenes installs them from an engine checkout until the engine publishes them.
</Note>

## Plugins the project needs

When packages of the project suggest plugins, a notification names them with **Install for this project** (in `.nanoforge/plugins`) and **Install for me** (every project, and kept in your account's plugin list). Plugins load once the editor reloads. In a folder you have not trusted, the notification only names them: the project's packages choose those names, so trust the folder first.

## Plugins can add checks

A plugin adds its own cards with the `PROJECT_CHECKS` extension point: see [Extension points](../plugins/extension-points).
